# Локальный AI в Averon Import

Локальный AI является **дополнительным** слоем проверки OCR. Обычное распознавание Tesseract работает независимо от него.

## Принцип безопасности

AI не изменяет строки автоматически. Сценарий:

```text
Tesseract → нормализация → строка Averon
                         ↓
                  AI-предложение
                         ↓
               сотрудник принимает
                или оставляет как есть
```

Для каждого OCR-поля сохраняются исходный текст, нормализованное значение, confidence и источник. Это позволяет сравнивать решение AI с тем, что реально прочитал OCR.

## Ollama

По умолчанию AI выключен. Для включения задайте переменные окружения перед запуском Averon Import:

```text
AVERON_AI_ENABLED=1
AVERON_AI_MODEL=<имя модели в Ollama>
```

При необходимости адрес Ollama можно изменить:

```text
AVERON_OLLAMA_URL=http://127.0.0.1:11434
```

Пример для PowerShell:

```powershell
$env:AVERON_AI_ENABLED="1"
$env:AVERON_AI_MODEL="<имя модели>"
.\start_windows.bat
```

Имя модели должно точно соответствовать модели, установленной в локальном Ollama. Averon проверяет доступность через локальный API Ollama.

## Интерфейс

Когда AI включён и модель доступна, в режиме проверки появляется кнопка **«AI-проверка строки»**.

Averon отправляет локальной модели:

- текущие значения строки;
- исходный OCR и нормализованные значения;
- confidence;
- вырезку исходной строки из PDF.

Модель возвращает только предложение. Пользователь видит сравнение **«Сейчас → AI»** и отдельно нажимает **«Принять предложения»**. После принятия строка получает статус `edited` и должна быть повторно проверена по PDF.

## Критические данные

Количество, единица, марка/тип и код учитываются отдельно через `critical_confidence`. Модель инструктируется не выдумывать количество, артикулы, DN/PN, мощность, размеры и другие технические параметры. Если значение не читается, корректный результат AI — отметить поле как неопределённое, а не угадывать его.

## Диагностика

`GET /api/health` содержит отдельный блок `ai`:

- `disabled` — AI выключен;
- `not_configured` — AI включён, но модель не указана;
- `unavailable` — локальный сервер недоступен;
- `model_missing` — Ollama работает, но нужная модель не найдена;
- `ready` — AI готов.

Рабочие PDF и запросы к модели при локальной конфигурации не требуют внешнего облачного AI API.
