# Минимальная проверка system-сообщений Qwen — offline preparation

Дата: 2026-10-28. Реальные запросы не выполнялись. Причина прежнего HTTP 400
остаётся неподтверждённой до ответа провайдера или контролируемого сравнения.

## Подготовленный вариант

При непустой подсказке клиент формирует ровно одно `system`:
`_PROMPT + "\n\n" + _USER_CONTEXT_POLICY`. Точный пользовательский текст остаётся
только в отдельной недоверенной текстовой части `user`, после номера страницы
и перед изображением. Исходная политика безопасности сохранена целиком.
Она запрещает по подсказке придумывать, заменять и нормализовать исходные
значения, отменять системные правила и обязательную проверку.

При `None` или пустой строке JSON запроса и hash основного промпта совпадают с
production baseline побайтно. Непустые пробелы сохраняются как пользовательский
контекст, лимит — 1000 символов, без обрезания. Модель, endpoint, DPI, изображение,
schema/strict, temperature, output cap и reasoning не меняются этим исправлением.

Учтены подтверждённые владельцем факты: production output cap **32768**;
**0 предметных строк до назначения человеком ролей — ожидаемое состояние UI**.
Логика ролей и интерфейс этим этапом не меняются.

## Checkpoint identity

Пустая подсказка сохраняет прежние descriptor и private scope. Для непустой:

* версия contextual policy — `document-context-v2-single-system`;
* точная подсказка по-прежнему связана HMAC с ключом только в private scope;
* добавлен hash фактически сериализованного шаблона запроса с фиксированными
  placeholders вместо документа/подсказки. Он включает policy, разбиение
  сообщений, метку контекста и остальные отправляемые параметры.

Изменение policy или layout инвалидирует contextual scope даже без ручного
изменения версии. Старый contextual manifest не возобновляется автоматически:
получается `checkpoint_identity_mismatch` до HTTP. Его файлы сохраняются;
оператор должен явно создать новый запуск/workspace.

## Диагностика и откат

Из первоначального предложения удалено поле диагностики из `PageAttempt`.
Схемы `page-*.json`, `manifest.json` и основного `report.json` сохранены.
Доказательства HTTP хранятся отдельно:

```text
checkpoint/
  manifest.json                 # прежняя версия 2
  page-000001.json               # прежняя схема, outcome/usage/cost
  request-diagnostics-v1/        # только при явном opt-in
    format.json                 # {"format_version": 1}
    request-<client-UUID>.json   # строго типизированный envelope версии 1
```

Opt-in: `CheckpointStore(..., capture_request_diagnostics=True)`.
По умолчанию capture выключен; production composition его не включает.
Envelope связывает evidence с fingerprint checkpoint, страницей и временем
начала попытки. Содержит только разрешённые размеры, счётчики, UUID и
структурированные коды/поля ошибки. Текст подсказки, промпт, error message,
HTTP body, Base64, содержимое PDF и credentials не записываются.

Приватный каталог/версия и возможность записи marker проверяются до workers.
Неизвестная/некорректная версия блокирует только явно включённый диагностический
запуск до HTTP. Обычный старый reader не читает sidecar. Сначала атомарно
сохраняется канонический outcome/usage, затем диагностический файл. Если второй
шаг не удался, диагностический run завершается безопасной ошибкой; результат и
usage остаются в checkpoint, автоматического повтора нет.

На синтетике проверен настоящий reader из baseline, дерево которого совпадает
с production `9d1a46f`: он читает новые canonical checkpoint и report при наличии
sidecar. Их байты при чтении не меняются. Откат приложения не требует удалять
sidecar или преобразовывать старые данные. Контекстные v1/v2 запросы при этом
намеренно имеют разные identities: читаемость результата не означает разрешение
продолжать распознавание с другим промптом.

## Минимальный live A/B: два запроса

Сериализатор `averon_import.tools.qwen_vision_ab_payloads.prepare_context_ab`
не имеет транспорта. Изолированный CLI `qwen_vision_ab_pilot` использует только
пару **B → A**, в отдельных одноразовых командах. Вспомогательный вариант C
проверяется offline, но недоступен через runner и не входит в текущий эксперимент:

| Case | system | user |
| --- | --- | --- |
| A | Два: основной промпт и отдельная policy, как в production baseline | Номер страницы, фиксированная подсказка H, тот же PNG |
| B | Один: основной промпт + policy | Точно тот же user, включая H и PNG |
| C, только offline | Один, как B | То же число частей user и та же метка подсказки, но сам текст H пуст |

Размер A и B одинаков: к B добавляется ровно **31 завершающий JSON-пробел**,
вне всех строк. Это допустимые JSON whitespace, которые не попадают в промпт.
C доводится такими же пробелами до того же размера. B без padding меньше A
ровно на 31 байт; его прирост к обычному запросу — `425 + J(H)`, для A —
`456 + J(H)`, где J — длина JSON-экранированного H в UTF-8 без внешних кавычек.
Значения schema и изображения не меняются для выравнивания.

Точный порядок будущего эксперимента:

1. Использовать оригинальную страницу **1 ПС1**, **DPI 115**, без crop.
   Один раз подготовить PNG; локально проверить его hash, геометрию, длину
   и отсутствие изменений между A/B. Исходный workspace не использовать для
   изменений. Создаётся отдельный приватный пакет эксперимента с собственной
   историей попыток, не связанной с checkpoint приложения.
2. Зафиксировать H только локально. Предпочтителен точный текст из неуспешной
   попытки, если он сохранился у оператора. Если он утрачен, согласовать новую
   короткую подсказку и честно обозначить, что сравнение относится к новому H.
   Не сокращать и не заменять H незаметно ради размера.
3. Зафиксировать модель/endpoint и все общие параметры: `reasoning_effort=none`,
   `max_completion_tokens=32768`, исходную schema/strict, temperature 0,
   store/stream false. Сохранить в безопасной сводке длины body **после padding**
   и число system; байты запросов не писать в отчёт. Будущий dispatcher должен
   отправить именно эти подготовленные bytes. Runner восстанавливает их из
   замороженных приватных PNG/H/model URI и проверяет точные hashes обоих body;
   при расхождении HTTP запрещён. Сам body не сохраняется.
4. Проверить ACL, credentials, применимые лимиты, общий token reserve и бюджет.
   Одна попытка на case: concurrency=1, max_requests=1. Один оператор/процесс,
   отсутствие параллельных работ с тем же ключом в пределах контролируемого
   окружения; внешний трафик этим не доказывается. Сохранить принятый cooldown.
5. После отдельного разрешения выполнить **B первым**. A — отдельная вторая
   команда оператора после просмотра безопасного результата B и cooldown
   **360 секунд**. Это разные case, не retry. Общий максимум — **две попытки**.
   После timeout, 429, 5xx, незавершённого ответа или unknown outcome runner
   блокирует A и повтор B. Никакого автоматического продолжения.
6. Сохранить safe diagnostics, HTTP status, finish reason, usage, время и
   расчётную стоимость. HTTP 200 означает приём запроса; `length` после 200
   означает отдельную проблему завершения ответа и не разрешает принять
   обрезанный JSON. Результат OCR допустим только после прежних проверок.

## Интерпретация и число запросов

| A | B | Вывод / действие |
| --- | --- | --- |
| 400 | 200 | Устранение двух-system представления убирает отказ при том же H, изображении и длине body. Structured code/param либо ответ поддержки должны подтвердить конкретный validator; не обобщать на все возможные запросы модели. |
| 200 | 200 | Старый отказ не воспроизведён; первопричина не доказана. Остановиться. |
| 200 | 400 | Объединённый вариант не прошёл; не включать его и не объявлять исправлением. |
| 400 | 400 | Пара не различила общий фактор. Остановиться, сохранить IDs и обратиться к поддержке. |

**Минимум для ожидаемого причинного контраста: 2 HTTP-попытки с возможной оплатой.**
Третий контроль запрещён в текущем runner и не предлагается как автоматический fallback.
Отдельная размерная пара ±1 байт около 1 MiB — ещё 2 запроса и отдельное
согласование, если поддержка/первые контроли оставят размерную гипотезу открытой.
Никаких таких запросов в рамках текущего offline задания нет.

## Резерв и финансовые ограничения

[Публичный синхронный тариф Yandex](https://aistudio.yandex.ru/ru/docs/ai-studio/pricing),
проверен 2026-10-28: Qwen3.6 35B — 0,20 ₽ вход, 0,05 ₽ cached input,
0,30 ₽ выход за 1000 токенов, с НДС. Это публичный профиль, а не проверка
индивидуальных условий аккаунта. Кеш в worst-case резерве не учитывать.

Общий входной резерв I должен покрывать текущий обоснованный baseline bound
плюс **максимальную** добавку среди A/B (`456 + J(H)`), а не меньшую добавку B.
Он не уменьшается произвольно. Проверить `I + 32768 <= 262144`, локальный TPM
и фактические ограничения аккаунта по принятой процедуре.

Максимальная расчётная стоимость одного case при этом тарифе:
`R = 0.20 * I / 1000 + 0.30 * 32768 / 1000 = 0.0002 * I + 9.8304 ₽`.
Пара A/B требует согласованного общего резерва `2R`.
Оператор передаёт явные действующие локальные ограничения в CLI; runner не
читает и не меняет production environment или настройки приложения.
Резерв входных токенов — предположение оператора с консервативной добавкой,
а не доказанный максимум hosted-токенизатора. Его нарушение блокирует A.
Автоматически повышать бюджет нельзя.
HTTP 400 без usage не следует считать бесплатным: стоимость остаётся неизвестной,
а резерв отправленной попытки не освобождается на основании предположения.

## Риски и offline-проверки

* Два последовательных вызова могут попасть на разные состояния backend;
  одна пара — ограниченное доказательство для выбранной конфигурации, IDs
  и структурированная причина отказа усиливают вывод.
* JSON whitespace допустим стандартом; его приём конкретным hosted endpoint
  ещё не проверен. B=200 подтвердит приём для B. Если оба case отклонены,
  нельзя приписать отказ числу system или содержимому H без дальнейших сведений.
* Даже успешный запрос может закончиться length/invalid JSON; повтор запрещён.
* Неизвестные коды и не-UUID provider IDs намеренно отбрасываются. Если причина
  есть только в свободном тексте, нужны UUID клиента и помощь поддержки.
* Нормальный режим без H сохраняет прежний wire format и identity. Context v1
  не продолжается как v2; старые результаты остаются читаемыми.

Offline tests проверяют policy, точность текста и изображения, равенство размеров
A/B/C, отсутствие HTTP в preparer, исходный payload A и пустой payload относительно
baseline, изменение identity при смене policy/layout без bump версии, отсутствие
секретов в diagnostics, sidecar version/ACL preflight и сохранность результата при
сбое записи. Mock-сценарии проверяют методику, не совместимость hosted модели.

Первоначальный профиль: **326 passed, 0 failed, 0 errors, 0 skipped**. Включены клиент,
адаптер, оркестратор, оба pilot CLI, диагностика, Human Review workflow и reliability.
Дополнительно выполнен независимый readback настоящим baseline reader, а также
сравнение 2 пустых запросов и 3 legacy A-запросов с исходной сериализацией:
все побайтно идентичны. Эти проверки использовали только синтетический PDF и fake HTTP.

## Изолированный runner: подготовка и будущий запуск

`averon_import.tools.qwen_vision_ab_pilot` не импортирует `main`, не запускает
ASGI и не использует AppSettingsService. Поэтому не создаёт data dir приложения,
не изменяет config/credentials/review/checkpoints. Endpoint разрешён только
`https://ai.api.cloud.yandex.net/v1`, модель — документированный URI Qwen без `/latest`.

Оператор готовит приватные UTF-8 файлы: точный H (до 1000 символов, без trim)
и JSON `{"model":"gpt://<folder_id>/qwen3.6-35b-a3b","base_url":"https://ai.api.cloud.yandex.net/v1"}`.
Ключ в JSON **запрещён** схемой. ACL существующих входных файлов не меняются:
их невозможность подтвердить блокирует подготовку. Новый run-dir создаётся
штатным приватным helper; проверяются DACL каталога и всех дочерних файлов.

Offline-команда (пути заменить разрешёнными локальными файлами):

```powershell
$AbInput = Join-Path $env:LOCALAPPDATA 'Averon\ab-test'
python -m averon_import.tools.qwen_vision_ab_pilot prepare `
  --pdf $PdfPath --context-file (Join-Path $AbInput 'ps1-h.txt') `
  --deployment-file (Join-Path $AbInput 'qwen-settings.json') `
  --output-root (Join-Path $AbInput 'isolated-runs') `
  --input-token-upper-bound 16384 --budget-rub 100 --rpm-limit 2 --tpm-limit 60000
python -m averon_import.tools.qwen_vision_ab_pilot preflight --run-dir $AbRun
```

Значения лимитов в примере явно сообщены оператором для этого эксперимента;
это не defaults и не подтверждённые квоты Yandex. Присвоить `$AbRun` точному
каталогу из вывода `prepare`. Нельзя создавать новый пакет, чтобы повторить
уже отправленный case. Не использовать общий production credentials одновременно
с другими заданиями; локальная блокировка пакета не доказывает отсутствия
внешнего трафика с тем же ключом.

**Следующие команды платные. Сейчас не выполнять. Требуется отдельное разрешение.**
Ключ берётся только из process-scoped `AVERON_YANDEX_AI_API_KEY` либо, при
явном `--use-windows-credential-manager`, из существующего Windows Credential
Manager в режиме чтения. Ничего не перезаписывается. Не передавать ключ в аргументах.

```powershell
$AbApproval = @('--allow-paid-api', '--confirm-live-preflight',
  '--accept-unverified-account-quotas', '--confirm-exclusive-key-use')
python -m averon_import.tools.qwen_vision_ab_pilot run-case --run-dir $AbRun --case B @AbApproval
# Остановиться; изучить B-report.json / B-diagnostics-v1.json.
# Только отдельным действием после cooldown и допустимого исхода B:
python -m averon_import.tools.qwen_vision_ab_pilot run-case --run-dir $AbRun --case A @AbApproval
```

`--confirm-live-preflight` подтверждает локальные проверки. Неизвестные квоты
остаются `unconfirmed`, риск принимается отдельным флагом. Последний флаг —
заявление оператора об исключительном использовании в контролируемом окружении,
не утверждение о возможности обнаружить все внешние клиенты.

На каждый case **до транспорта** создаётся постоянный `<case>-intent.json`
с fsync и полной резервируемой стоимостью. Файл никогда не удаляется автоматически.
Crash/ошибка записи после intent расходует слот; повтор запрещён. A требует
terminal B-report и тот же приватно HMAC-связанный ключ. A/B имеют отдельные
diagnostic envelopes версии 1 и отдельные отчёты. UUID и строго разрешённые коды
сохраняются даже при HTTP 400; свободный текст провайдера не сохраняется.
При `stop` + успешной schema/page validation транскрипция записывается отдельно;
при `length` обрезанное содержимое не восстанавливается и не принимается.
Неизвестная стоимость остаётся `null`, intent-резерв не освобождается.

В безопасную сводку передавать только HTTP status, finish reason, usage, время,
оценку стоимости, разрешённые error code/type/param и UUID. Не передавать
`plan.json`, `context.txt`, `image.png`, `*-transcription.json` или raw body в
AI-сессию, GitHub и технические логи. Файлы приватного пакета хранятся **7 дней**;
после срока live блокируется. Удаление — оператором только выбранного run-dir
после проверки абсолютного пути, без удаления исходного PDF, H, конфигурации
или старых checkpoints. Это обычное удаление, не гарантия стирания с SSD/бэкапов.

Финальная проверка перед публикацией: **359 passed, 0 failed, 0 errors,
0 skipped** в десяти профильных файлах, включая 33 новых проверки runner.
Весь HTTP в тестах runner заблокирован, используются только fake responses и
синтетические PDF/H. Отдельная локальная сверка разрешённых оператором файлов
подтвердила побайтное совпадение A с production-сериализатором и неизменность
обычного запроса без H. Индивидуальные клиентские метрики/артефакты в Git не включены.
