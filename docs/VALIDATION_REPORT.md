# Отчёт проверки Averon Import 1.0.0-rc1

## Проверенное окружение

- Linux x86_64 (контейнер разработки);
- Python 3.13;
- Tesseract OCR 5.5.0;
- языки `rus` и `eng`;
- исходный документ: рабочая документация ОВиК, 58 страниц.

## Автоматические тесты

Запущены модульные и интеграционные тесты:

- разбор диапазонов страниц;
- нормализация размеров, единиц измерения и чисел;
- формирование Excel с выбранными столбцами;
- наличие подписи разработчика на листе сведений;
- обнаружение девяти столбцов на реальной странице спецификации.

Результат: **8 тестов пройдено**.

## Сквозной функциональный тест

Проверена цепочка:

```text
загрузка PDF → изображение страницы → OCR → сохранение результата → экспорт XLSX
```

Результаты:

- PDF принят: 58 страниц, около 5,6 МБ;
- автоматический поиск корректно предложил страницы спецификации **18-58**;
- страницы 18-20 обработаны при 300 DPI;
- найдено 52 непустые строки;
- 32 строки получили статус «Распознано»;
- 19 строк получили статус «Требует проверки»;
- 1 строка получила статус «Не распознано»;
- ошибок обработки страниц: 0;
- время обработки трёх страниц в тестовом окружении: около 10 секунд;
- сформирован корректный XLSX-архив с листами «Спецификация» и «Сведения»;
- проверена запись выбранных столбцов, числового количества и строки
  «Андриянов Степан Владимирович - НВСС».

## Что эти цифры не означают

Статусы основаны на уверенности OCR и структурных проверках. Это **не измерение фактической точности относительно вручную подготовленного эталонного Excel**. Для расчёта точности наименований, марок, количества и единиц измерения потребуется эталон, проверенный инженером-сметчиком.

## Вывод

Версия является рабочим релиз-кандидатом для пилотной эксплуатации на спецификациях текущей формы. Перед промышленным внедрением рекомендуется:

1. проверить весь диапазон 18-58;
2. подготовить эталонный Excel минимум для 3-5 документов;
3. измерить ошибки критических полей;
4. согласовать регламент обязательной проверки строк;
5. собрать Windows-версию на целевом компьютере.

Проверены оба программных пути OCR. В тестовом Linux-окружении для точного пути использовались доступные локальные модели Tesseract через `AVERON_BEST_TESSDATA_DIR`; скачивание официальных `tessdata_best` выполняется уже на Windows скриптом установки.

- 46 строк со статусом «Распознано»;
- 6 строк со статусом «Требует проверки»;
- ошибок страниц: 0;
- типы: 39 позиций, 11 компонентов, 1 раздел, 1 система;
- время тестового прогона: около 19 секунд;
- создан корректный `.xlsx`;
- автоматические тесты: 13 пройдено, 1 интеграционный тест пропущен при отсутствии внешнего образца.

Сравнение с экспортом rc5 показало заметное исправление типовых строк: «приточная установка», «моноблочная», «фильтр», «гибкие вставки», «щит управления», «диф. реле давления», «датчик канальной температуры», производитель «Арктика», единицы `шт.`, `компл.`, `м²`. Короткие системные обозначения, отдельные артикулы и мелкие примечания всё ещё требуют проверки инженером.

## Проверка исправления rc7

Исправлен Windows-специфичный сбой точного режима, при котором `pytesseract`
передавал кавычки из аргумента `--tessdata-dir` как часть пути. В результате
Tesseract пытался открыть файл вида `tessdata_best"/rus.traineddata`.

Новая реализация передаёт каталог моделей через временную переменную процесса
`TESSDATA_PREFIX` без кавычек. Системные настройки Windows не изменяются, а
исходное значение окружения восстанавливается после каждого вызова OCR.

Проверки:

- 14 модульных тестов пройдено, 1 интеграционный тест пропущен без образца;
- точный OCR успешно обработал страницу 19 текущего PDF;
- распознано 22 строки, ошибок страницы — 0;
- каталог моделей намеренно размещался в пути с пробелами и кириллицей;
- первая позиция распознана как «Воздуховод 1000×700 из оцинкованной стали толщ. 0,7 мм».
