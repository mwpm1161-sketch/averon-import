# AI-first local review MVP (V2D)

V2D adds an experimental AI-first workflow inside the existing Averon Import interface. These additions apply only to AI-first; the standard OCR remains a temporary fallback with its current behavior. AI-first uses the existing document workspace and PDF renderer, and stores `transcription.json`, a content-free technical `report.json`, page progress, review decisions, and the orchestration checkpoint in a separate `ai_first` directory for that document. It does not write the legacy `result.json` or review ledger. A separately marked pilot XLSX can be downloaded from saved Human Review decisions; it is not the standard commercial export and does not enable sourcing.

## Offline manual test on Windows

Start the existing Averon app from the isolated feature worktree with the synthetic adapter enabled:

```powershell
$env:AVERON_AI_FIRST_UI_ENABLED = '1'
$env:AVERON_AI_FIRST_FAKE_OCR = '1'
$env:AVERON_AI_FIRST_LIVE_ENABLED = '0'
python -m averon_import.main --host 127.0.0.1 --port 8765
```

Open `http://127.0.0.1:8765`, sign in through the configured local test authentication, upload a PDF, and choose **AI-first · синтетический тест** in the page panel. The AI-first mode selects every PDF page by default; the existing range field remains available to narrow the selection. The fake adapter returns clearly labelled synthetic rows and never reads the rendered page or makes HTTP requests. The PDF is rendered locally so the side-by-side review and navigation can be exercised.

The review screen supports editing cell values, assigning a Human Review role to each row, linking a component to a manually classified standalone parent, adding a manual row, excluding a row through an explicit review decision, resolving remarks with a note, confirming selected values, and confirming page completeness separately. Roles are never inherited from the model. A role change invalidates related confirmations while preserving their audit record and saved correction. Every change is saved to the private local review ledger. The original extracted cells remain in the draft. Rows with linked remarks or uncertain cells are highlighted. A successful row confirmation does not resolve page remarks or confirm page completeness.

Each AI-first row has one visible review state derived from the current extraction, Human Review ledger, current role, saved value decision, relevant row/table/page remarks, and original uncertainty flags. Open remarks, unassigned or stale roles, stale value decisions, and incomplete page processing remain in the attention state. Saved value review and readiness for the pilot workbook are shown separately; workbook admission additionally requires the existing backend conditions, including an explicit standalone role, resolved blocking evidence, and page completeness. Service rows and excluded rows remain visible in a neutral state. Editing a cell immediately marks the row as unsaved. **Сохранить черновик проверки** warns and does not claim success while edits, role changes, remark notes, or a manual row remain only in browser controls.

The AI-first table can be searched across source and reviewed values, filtered by attention, unassigned role, checked, corrected, excluded, or service rows, and stepped through with **Следующая строка для проверки**. Rows are grouped by their source table so that unrelated column layouts are never merged into one grid. Group actions apply only to selected rows visible under the current page and filter. Bulk role assignment and bulk value confirmation reject unresolved remarks and uncertain cells, run atomically, and keep the selection if the server refuses the request. They do not confirm page completeness. Saving a correction records it in the review ledger without treating it as confirmed; the saved value stays visible across reload and is admitted to the checked sheet only after a separate confirmation.

Excluding a row keeps its last reviewed cell values in the review ledger and audit history. Restoring it asks the reviewer to inspect the displayed values and confirm them explicitly; a saved correction is restored as a corrected decision. Remarks held on the page object can be resolved through the same audited action as draft-level remarks, and page-only issue resolutions are invalidated when that page is reprocessed.

## Test XLSX and source-page location

In the page summary, select one to three successfully processed pages using **В тестовый XLSX**. Check that the selected page is complete, resolve relevant remarks, assign each row's role, correct and confirm values, and confirm page completeness. If rows still have no Human Review role, the interface explains that they will remain source rows and asks before confirming page completeness. Then choose **Скачать тестовый XLSX**. The workbook has a convenient confirmed-positions sheet, a row register, a separate ordinary-cell sheet for each source table, per-page sheets for manual rows, selected-page coverage, and the full structured extraction for those pages. Each source-table sheet preserves source columns in order, including blank and repeated headers, and shows original and reviewed values side by side. Pages outside the chosen fragment are explicitly marked as outside the export scope; the workbook is labelled **ТЕСТ** and is not a commercial estimate.

The pilot workbook is generated by a separate AI-first route with its own page-scoped checks. It does not call the standard Excel exporter, change the production export guard, or connect to sourcing. Only rows with an active Human Review decision, an explicit standalone role, a completed page, confirmed page completeness, and no unresolved row- or table-level issue appear in **Проверенные позиции**. Other rows remain in **Все распознанные строки** with their saved review status and a link to their source-table worksheet. The confirmed-positions sheet fills standardized fields only when one source header maps unambiguously; every source value remains visible in the row's table worksheet even when no field is mapped or a mapping is ambiguous.

The page summary disables export selection for pages that have not completed and shows why they are unavailable. Selecting one to three completed pages triggers a content-free server preview using the same admission rules as workbook generation; the download stays disabled if that check fails. The preview reports how many recognized rows and confirmed standalone positions are in scope, without exposing cell contents. The PDF pane has bounded zoom controls for fit-to-width, 100%, and stepwise zoom. Progress and processing failures remain separate from content remarks and cannot be confirmed as review issues.

Source-column identity is based on the source page, table, and zero-based column index, not the header text. Current known aliases remain small helper rules. Any future semantic mapping must be stored as an unconfirmed candidate with its own provenance; a smetchnik's explicit assignment belongs in the Human Review ledger and is authoritative. Neither an alias nor a semantic candidate may rewrite the source header, raw cell value, or count as a human confirmation.

Selecting a recognized row asks a local PDF text-layer locator for a unique exact match and then uses Averon's existing row-highlight renderer. A cell click asks for a unique match of that source cell. If the PDF has no searchable text layer, or the match is missing or duplicated, Averon shows the selected page without drawing a guessed rectangle. Model-proposed boxes are not treated as proof; scanned pages therefore receive page navigation only until an independent matching source is available.

To return to a saved AI-first draft, reopen that document and use **Открыть AI-first проверку**. The app stores the source transcription and review ledger in the document's private `ai_first` subdirectory. The checkpoint uses the existing fail-closed ACL verification. On Windows, each created directory and protected file is checked against its final DACL before use; parent workspace ACLs are not modified. Use Averon's existing document deletion workflow to remove the complete workspace, including the AI-first checkpoint. Do not delete a checkpoint while a job is active.

## Qwen mode boundary

The Qwen option is hidden unless the local server is explicitly restarted with `AVERON_AI_FIRST_LIVE_ENABLED=1` as well as `AVERON_AI_FIRST_UI_ENABLED=1`. The operator must also supply local request, token, input-reservation, price, and budget caps through `AVERON_AI_FIRST_MAX_REQUESTS`, `AVERON_AI_FIRST_RPM_LIMIT`, `AVERON_AI_FIRST_TPM_LIMIT`, `AVERON_AI_FIRST_INPUT_TOKEN_UPPER_BOUND`, `AVERON_AI_FIRST_MAX_BUDGET_RUB`, `AVERON_AI_FIRST_INPUT_RUB_PER_1K`, `AVERON_AI_FIRST_OUTPUT_RUB_PER_1K`, and optionally `AVERON_AI_FIRST_CACHED_INPUT_RUB_PER_1K`. The output cap, DPI, and request timeout use `AVERON_AI_FIRST_MAX_OUTPUT_TOKENS` (maximum 32768), `AVERON_AI_FIRST_DPI`, and `AVERON_AI_FIRST_REQUEST_TIMEOUT_S` (maximum 300 seconds). The existing Yandex AI Studio model settings and secret store supply the model URI, endpoint, and credential; the local workflow accepts only the documented Qwen3.6 35B model URI shape and Yandex AI Studio endpoint.

These values are local application limits. They do not verify account RPM/TPM. The live UI requires a separate per-run confirmation before submitting the selected pages; that control is not permission for a future paid experiment. No live Qwen request was made while preparing V2D. The Qwen context fingerprint binds the exact user hint without placing its text in public reports. After reopening the app, re-enter the same hint to resume the same checkpoint; a changed hint safely creates an identity mismatch and cannot reuse the old extraction.

The local Qwen runtime uses concurrency 1, no automatic retry, and the existing orchestration budget and checkpoint rules. Failed, incomplete, and unknown-outcome pages appear as retry candidates only; the operator must select pages for a retry explicitly. A retry of an unknown outcome can incur a second charge. Cancellation waits for an in-flight client call to return and preserves any completed page records and usage in the checkpoint.

## Review and export boundary

AI-first review decisions do not create a legacy Yandex OCR result and do not change M6 or sourcing inputs. The test-only pilot workbook is deliberately separate from the production Excel path. It does not relax or bypass the production export guard, does not claim a commercial estimate, and does not make the result eligible for sourcing.
